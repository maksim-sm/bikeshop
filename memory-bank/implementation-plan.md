# План имплементации

План для первой версии магазина из `design-document.md`. Инструменты — из `tech-stack.md`. Ограничения — из `ai-rules.md`.

Выполнять шаги по порядку. Шаг закончен только после его теста. Следующий шаг не начинать, пока текущий тест не проходит. Тексты интерфейса — на русском. Онлайн-оплату и платёжного провайдера не делать.

Деньги хранить целым числом копеек. Типы товаров: городской, горный, шоссейный, детский, электровелосипед, аксессуар. Размеры рамы взрослых: XS, S, M, L, XL. Детские размеры: 12, 16, 20, 24. У аксессуара размера нет.

Приложение разместить в корне репозитория. Эти документы лежат в `memory-bank/`.

## 1. Каркас приложения

Создать приложение Next.js с TypeScript, App Router и Tailwind CSS. Язык страницы — русский. Запустить его локально.

**Тест.** Главная страница открывается в браузере на компьютере. В консоли браузера нет ошибок. Сборка проекта завершается без ошибок.

## 2. База и Prisma

Поднять PostgreSQL. Подключить Prisma через переменную окружения с адресом базы. Сгенерировать клиент. Пока не добавлять таблицы магазина.

**Тест.** Команда проверки подключения Prisma завершается успешно и видит эту базу.

## 3. Товар

Добавить миграцией таблицу товара: название, уникальный адресный слаг, бренд, тип, описание, цена в копейках, признак «скрыт» (по умолчанию товар виден), счётчик продаж (по умолчанию ноль), дата создания.

**Тест.** Миграция применяется к пустой базе повторно без ручной правки. Товар каждого из шести типов сохраняется и читается обратно с теми же названием, ценой, брендом и признаком скрытия.

## 4. Размер и остаток

Добавить миграцией варианты товара: ссылка на товар, размер рамы (пусто для аксессуара), остаток (целое, не меньше нуля), дата ожидаемой поставки (необязательна). Пара «товар + размер» уникальна. Пустой размер у одного товара тоже может быть только один.

**Тест.** У велосипеда сохраняются два размера с разным остатком. Повтор того же размера отклоняется. Аксессуар сохраняется с пустым размером. Отрицательный остаток отклоняется.

## 5. Характеристики

Добавить миграцией необязательные поля товара: число скоростей, вес, материал рамы.

**Тест.** У велосипеда поля сохраняются и читаются. У аксессуара они остаются пустыми, запись при этом успешна.

## 6. Ссылки на фото

Добавить миграцией фото товара: ссылка, порядок сортировки, связь с товаром.

**Тест.** У товара сохраняются два фото. После чтения они приходят в заданном порядке. В базе лежит ссылка, а не содержимое файла.

## 7. Индексы каталога

Добавить миграцией расширение `pg_trgm` и индексы для фильтров и поиска: тип, бренд, цена, признак скрытия, поиск по названию и бренду.

**Тест.** Миграция применяется на чистой базе. Повторный запуск миграций ничего не меняет.

## 8. Начальные данные

Сделать повторяемый начальный набор: несколько велосипедов разных типов и брендов, один аксессуар, один скрытый товар, размер с нулевым остатком и датой поставки, размер с нулевым остатком без даты, размер с положительным остатком. У товаров задать разные цены, даты создания и счётчики продаж. Фото можно указать внешними ссылками.

**Тест.** Повторный запуск не плодит дубликаты. В базе есть и видимые, и скрытый товар, и оба случая нулевого остатка.

## 9. Каталог

Сделать страницу каталога. На карточке в списке показать первое фото, название, цену и наличие. Товар в наличии, если хотя бы у одного варианта остаток больше нуля. Скрытые товары не показывать. Цена показывается в рублях и копейках.

**Тест.** В браузере видны только товары из начального набора, которые не скрыты. Скрытый товар отсутствует. Товар без остатка помечен как отсутствующий. Цена совпадает с ценой в базе.

## 10. Карточка товара

Сделать страницу товара по слагу. Показать фото в заданном порядке, цену, наличие, тип, размеры, скорости, вес, материал рамы и описание. Пустые характеристики не показывать.

**Тест.** Открывается товар из начального набора, и на странице видны только заполненные характеристики. Несуществующий слаг показывает понятную страницу «не найдено» на русском, без падения сервера.

## 11. Выбор размера

На карточке велосипеда дать выбор размера. По умолчанию выбран размер с остатком больше нуля. Для размера без остатка кнопка «В корзину» недоступна. Дату поставки показывать только если она задана. У аксессуара выбора размера нет, кнопка зависит от его единственного остатка.

**Тест.** Размер с датой поставки: кнопка недоступна, дата видна. Размер без даты: кнопка недоступна, даты нет. Размер в наличии: кнопка доступна. Аксессуар без остатка нельзя добавить, аксессуар в наличии — можно нажать кнопку.

## 12. Фильтры

На каталоге добавить фильтры: тип, размер рамы, диапазон цены, бренд, наличие. Фильтры сочетаются. Добавить сброс фильтров.

**Тест.** Каждый фильтр по отдельности сужает список ожидаемым образом. Два фильтра сразу показывают только пересечение. Выбор размера скрывает аксессуары. Скрытый товар не появляется ни при каком фильтре. Сброс возвращает полный видимый каталог.

## 13. Сортировка

Добавить сортировку: цена по возрастанию, цена по убыванию, новинки по дате создания, популярность по счётчику продаж.

**Тест.** Для каждого режима порядок карточек в браузере совпадает с порядком этих полей в начальных данных. Переключение режима не сбрасывает уже выбранные фильтры.

## 14. Поиск

Добавить поиск по части названия и по бренду. Поиск работает вместе с фильтрами и сортировкой. Пустой запрос оставляет текущую выборку. Если ничего не найдено, показать короткий текст на русском.

**Тест.** Часть названия находит нужный велосипед и не находит чужие. Поиск по бренду находит все видимые товары этого бренда. Поиск вместе с фильтром типа оставляет только совпадение по обоим условиям. Запрос без совпадений показывает пустое состояние, а не ошибку.

## 15. Скорость каталога

Временно наполнить базу тремя тысячами видимых товаров с вариантами, брендами и ценами. Выполнить типичный фильтр по типу и цене и поиск по части названия.

**Тест.** Каждая из двух операций возвращает результат быстрее двух секунд. После проверки временные товары удалить, начальный набор сохранить.

## 16. Сессия и корзина

Завести сессию посетителя в cookie. В базе хранить корзину этой сессии и строки: товар, вариант, количество, цена в копейках на момент добавления. У гостя корзина создаётся при первом добавлении.

**Тест.** Два разных браузера получают две разные корзины. Обновление страницы не создаёт вторую корзину тому же браузеру.

## 17. Добавление в корзину

По нажатию «В корзину» добавлять выбранный вариант в корзину этой сессии. Если строка этого варианта уже есть, увеличивать количество. Количество в корзине не может стать больше остатка. Скрытый товар и вариант без остатка добавить нельзя.

**Тест.** Первое нажатие создаёт строку с количеством 1 и ценой, равной текущей цене товара. Повторное нажатие увеличивает количество. Попытка превысить остаток оставляет количество равным остатку и показывает сообщение на русском.

## 18. Страница корзины

Сделать страницу корзины: фото, название, размер, цена строки, количество, сумма строки, итог. Количество можно изменить и строку можно удалить. Итог считает сервер.

**Тест.** Смена количества меняет сумму строки и итог. Удаление убирает строку. Количество меньше единицы не сохраняется. После обновления страницы состав корзины тот же.

## 19. Фиксация цены

Цена в строке корзины остаётся той, что была при добавлении.

**Тест.** Добавить товар в корзину, затем изменить цену товара в базе. Каталог показывает новую цену. Корзина показывает старую цену и старый итог. Новое добавление того же варианта после смены цены использует уже новую цену только для новой логики, описанной так: существующая строка не пересчитывается. Закрепить этот сценарий автоматическим тестом.

## 20. Форма заказа

Сделать страницу оформления с составом заказа и итогом. Поля: имя, телефон, email, доставка «курьер» или «самовывоз», адрес. Адрес спрашивать и требовать только для курьера. Способ оплаты на форме один — «при получении»; он выбран и не редактируется. Полей карты нет. Для пустой корзины вместо формы показать ссылку в каталог.

**Тест.** Переключение на самовывоз скрывает адрес, и заказ по этому шагу можно заполнить без адреса. Переключение на курьера снова требует адрес. На странице нет поля номера карты. Пустая корзина не показывает форму.

## 21. Создание заказа

По подтверждению создать заказ в одной транзакции: ещё раз проверить остаток каждой строки, списать остаток, записать заказ и строки заказа с названием, размером, количеством и ценой из корзины, присвоить уникальный номер, поставить статус «принят», очистить корзину, увеличить счётчик продаж товара на купленное количество. Контакты и доставка сохраняются на заказе. Гость оформляет без регистрации.

**Тест.** Гость проходит путь от корзины до страницы с номером заказа. Остаток в базе уменьшился на купленное количество. Корзина пуста. В заказе цена строк равна цене, которая была в корзине, а статус — «принят». Счётчик продаж вырос на это количество.

## 22. Нехватка остатка

Если к моменту подтверждения остатка уже не хватает, заказ не создавать и остаток не уводить в минус. Показать, какой позиции не хватает. Корзину сохранить.

**Тест.** Положить товар в корзину, обнулить его остаток, подтвердить заказ. Заказа нет, остаток остался нулём, корзина на месте, на экране названа проблемная позиция. Закрепить сценарий автоматическим тестом.

## 23. Последняя единица

Два подтверждения заказа на одну оставшуюся единицу товара обработать так, чтобы победил только один.

**Тест.** Два параллельных подтверждения при остатке 1 дают ровно один заказ. Остаток становится нулём. Второй ответ сообщает о нехватке. Закрепить сценарий автоматическим тестом.

## 24. Письмо

После успешного заказа отправить письмо через SMTP магазина на email из заказа. В письме — номер заказа и состав с количествами и ценами. Адрес, порт, отправителя и учётные данные SMTP взять из переменных окружения. Ошибку отправки записать в лог сервера и не отменять заказ.

**Тест.** При рабочем SMTP письмо приходит на указанный ящик, номер и состав совпадают с заказом. При намеренно неверном адресе SMTP заказ остаётся в базе со статусом «принят», а в логе есть ошибка отправки.

## 25. Регистрация и вход

Подключить Auth.js: регистрация и вход по email и паролю, выход. Повтор email не регистрировать. Пароль хранить только как хеш.

**Тест.** Новый покупатель регистрируется, выходит и входит тем же паролем. Повторная регистрация с тем же email отклоняется с сообщением на русском. В базе нет открытого пароля.

## 26. История заказов

Сделать страницу кабинета со списком заказов вошедшего покупателя и страницу одного заказа. Показать номер, дату, состав, итог, доставку и статус на русском. Статусы: принят, собирается, передан в доставку, готов к выдаче, выполнен, отменён. Гостю вместо истории показать вход.

**Тест.** Покупатель видит только заказ, оформленный под его учётной записью. Прямой адрес чужого заказа ему недоступен. Гость со страницы истории попадает на вход.

## 27. Корзина при входе

Корзина сессии после входа принадлежит пользователю. Если у пользователя уже была корзина, объединить строки одного и того же варианта. Суммарное количество не превышает остаток. Цена в строке остаётся ценой более раннего добавления.

**Тест.** Гость кладёт товар, входит — товар на месте. Второй случай: тот же вариант уже лежит в корзине пользователя; после входа количество объединено и не выше остатка, цена не пересчитана по новой цене товара.

## 28. Роль менеджера

Добавить пользователю роль покупателя или менеджера. Покупатель — роль по умолчанию. Доступ к `/admin` только у менеджера. В начальных данных завести одного менеджера.

**Тест.** Менеджер открывает `/admin`. Покупатель и гость по этому адресу получают отказ: гость — на страницу входа, покупатель — отказ без содержимого админки.

## 29. Товары в админке

Сделать список товаров, создание и редактирование: название, бренд, тип, описание, цена, характеристики, скрытие, варианты с остатком и датой поставки. Скрытый товар пропадает из каталога и остаётся в админке. Новый видимый товар появляется в каталоге.

**Тест.** Менеджер создаёт велосипед с двумя размерами, и тот виден в каталоге. После включения скрытия он пропадает из каталога и открывается в админке. Смена цены меняет каталог и не меняет цену уже лежащей строки корзины.

## 30. Загрузка фото

В форме товара загружать изображения в S3-совместимое хранилище. Адрес, бакет и ключи взять из переменных окружения. В базе сохранять ссылку и порядок. На карточке и в каталоге показывать загруженное фото.

**Тест.** После загрузки двух фото они видны в каталоге и на карточке в выбранном порядке. В базе у фото есть только ссылка.

## 31. Заказы в админке

Показать менеджеру список заказов с номером, датой, контактом, итогом и статусом. Дать смену статуса только внутри списка из шага 26. Покупатель видит новый статус в кабинете.

**Тест.** Менеджер переводит заказ по каждому допустимому статусу, и покупатель видит тот же статус. Значение вне списка сохраняется нельзя: статус в базе не меняется.

## 32. События воронки

Завести таблицу событий визита. Писать четыре вида: просмотр карточки, добавление в корзину, начало оформления, созданный заказ. Событие связано с сессией. Просмотр писать при открытии карточки, добавление — при успешном добавлении, начало оформления — при открытии формы непустой корзины, заказ — после успешного создания.

**Тест.** Один такой проход создаёт по одному событию каждого вида. Повторное открытие карточки добавляет ещё один просмотр. Неудачное оформление из шага 22 не пишет событие «созданный заказ».

## 33. Метрики в админке

На одной странице админки показать за выбранные даты:

- долю визитов, в которых открыта хотя бы одна карточка;
- долю добавлений в корзину от числа просмотров карточек;
- долю визитов с непустой корзиной, которые закончились заказом;
- число заказов за последние семь дней.

Визит — одна сессия. Число заказов считать по дате создания заказа, включая позже отменённые.

**Тест.** На контролируемом наборе из шагов 32 и 21 цифры на странице совпадают с ручным подсчётом. Заказ старше семи дней в недельное число не входит. Покупатель эту страницу не открывает.

## 34. Телефон и компьютер

Пройти каталог, фильтры, карточку, корзину, оформление, кабинет и админку на узкой ширине телефона и на ширине компьютера.

**Тест.** На обеих ширинах нет горизонтальной прокрутки страницы. Фильтром можно воспользоваться, заказ гостя доходит до номера, менеджер открывает список заказов.

## 35. Сквозная проверка

Повторить четыре сценария на свежих начальных данных, в браузере.

**Тест.** Все четыре условия выполнены:

- гость оформляет заказ с доставкой курьером и видит номер;
- подтверждение при нулевом остатке не создаёт заказ;
- после смены цены товара итог уже собранной корзины не меняется;
- покупатель не открывает админку, менеджер открывает.
