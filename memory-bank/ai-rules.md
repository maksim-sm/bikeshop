# Правила для ИИ-разработчика

Эти правила действуют на весь код магазина. Источники правды: `design-document.md` (что делает продукт) и `tech-stack.md` (чем это делается). Если они расходятся, поведение берётся из PRD, а инструменты — из стека. Исключение: онлайн-оплата картой описана в PRD, но в стеке отложена. Её не реализовывать, пока это явно не попросят.

## Как вести задачу

1. Прочитать оба документа и существующий код по затронутому месту. Не выдумывать экраны, поля и роли.
2. Брать один пользовательский сценарий за раз: каталог, карточка, корзина, оформление, кабинет или админка. Довести его до рабочего состояния, потом переходить к следующему.
3. Не расширять объём. Вне первой версии: маркетплейс, бонусы, мобильное приложение, сборка и сервис на дому, платёжный провайдер, отдельный поиск, отдельная аналитика, отдельные сервисы.
4. Не добавлять зависимость, сервис или слой абстракций, если задачу закрывает текущий стек.
5. Писать по-русски всё, что видит покупатель и менеджер.

## Стек

- Приложение — Next.js (TypeScript, App Router), React, Tailwind CSS. Витрина, кабинет и админка живут в одном проекте.
- Данные читаются и меняются на сервере. Отдельный API не заводить.
- База — PostgreSQL. Схема и запросы — только через Prisma и миграции. Схему руками в обход миграций не менять.
- Вход и роли — Auth.js. Регистрация по email и паролю нужна только для истории заказов.
- Фото — в S3-совместимом хранилище. В базе хранится ссылка.
- Письмо о заказе — через SMTP магазина.
- Админка — страницы `/admin`. Туда пускает только роль менеджера.

## Деньги, остатки и заказ

- Цена копируется в строку корзины в момент добавления. Дальнейшее изменение цены товара не меняет уже лежащую в корзине сумму.
- Количество в корзине не может превысить остаток. Итог считается на сервере.
- Оформление заказа повторно проверяет остаток. Если товара не хватает, заказ не создаётся, покупатель видит, какой позиции не хватает.
- Списание остатка и создание заказа происходят в одной транзакции.
- Гость оформляет заказ без аккаунта. Корзина привязана к сессии. После входа та же корзина принадлежит пользователю.
- В этой версии единственный способ оплаты — при получении. Заказ сразу получает статус «принят». Данные карты не принимать и не хранить.
- Доставка — курьер или самовывоз. Адрес спрашивается только для курьера.
- После успешного заказа уходит письмо с номером и составом. Сбой письма не отменяет уже созданный заказ; ошибку отправки нужно видеть в логах.
- Покупатель видит только заказы, оформленные после входа в его учётную запись. Заказ гостя остаётся без пользователя. Статусы: принят, собирается, передан в доставку, готов к выдаче, выполнен, отменён.
- Переход заказа в статус «отменён» в той же транзакции возвращает количество каждой строки на склад. Повторное сохранение статуса «отменён» остаток не меняет. Переход из «отменён» в другой статус снова списывает это количество; если остатка не хватает, статус остаётся «отменён».

## Каталог

- В списке есть фото, название, цена и наличие. Скрытый менеджером товар в каталог не попадает.
- Фильтры: тип, размер рамы, цена, бренд, наличие. Сортировка: цена, новизна, популярность. Поиск — по названию и бренду через `ILIKE` и индекс `pg_trgm`.
- Не подключать отдельный поисковый движок. На нескольких тысячах товаров ответ должен укладываться в одну-две секунды.
- Если выбранного размера рамы нет, кнопка «В корзину» недоступна. Дату ожидаемой поставки показывать только когда она задана.
- Каталог, фильтры и оформление работают на ширине телефона и компьютера.

## Метрики

Писать в ту же базу четыре события: просмотр карточки, добавление в корзину, начало оформления, созданный заказ. Не подключать стороннюю аналитику. Число заказов за неделю считать по таблице заказов.

## Проверка

Перед завершением задачи прогнать затронутый сценарий так, как его проходит покупатель или менеджер.

Для заказа обязательно проверить: гостевое оформление, отказ при нулевом остатке, неизменность цены в корзине после смены цены товара, недоступность админки без роли менеджера.

Не объявлять задачу сделанной по одному только успешному типу или сборке, если сценарий в браузере не пройден.
